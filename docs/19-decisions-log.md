## Accepted
**D-001 — Native apps on both platforms (Swift + Kotlin), no shared UI/logic framework** — Accepted — 2026-10-19
Founder's choice. Best access to AlarmKit, camera and on-device ML. Cost: logic duplicated → mitigated by shared specs, codegen and test vectors with a CI parity job.

**D-002 — Backend: Supabase (EU region)** — Accepted — 2026-10-19
Postgres + RLS fits leaderboards/clans; Realtime for battles & chat; Edge Functions for authoritative logic; pg_cron for periodic jobs.

**D-003 — English-only UI, localizable from day one** — Accepted — 2026-10-19

**D-004 — iOS minimum iOS 26** — Accepted — 2026-10-19
AlarmKit (alarms that break through Silent mode and Focus) requires iOS 26. Older iOS versions cannot provide a reliable alarm for third-party apps.

**D-005 — Android minSdk 29** — Accepted — 2026-10-19

**D-006 — Pose model: MediaPipe Pose Landmarker on both platforms** — Accepted — 2026-10-19
Same 33-landmark topology on both platforms → one RepEngine spec and shared test vectors. Apple Vision / ML Kit rejected for parity reasons. iOS via SPM (`MediaPipeTasksVision`), CPU-only on iOS — validated in spike P3-01. Licence: Apache 2.0.

**D-007 — Rep counting = deterministic heuristic state machine (v1), learned validator later** — Accepted — 2026-10-19
Explainable, testable, identical across platforms. A learned model is added later only as a second opinion for anti-cheat.

**D-008 — Battle video: LiveKit Cloud (SFU)** — Accepted — 2026-10-19
Swift and Kotlin SDKs, data channels, free Build tier for development; self-hostable (open source) if costs grow. No recording.

**D-009 — Purchases via RevenueCat** — Accepted — 2026-10-19

**D-010 — Ads via AdMob + UMP** — Accepted — 2026-10-19

**D-011 — Global competitive periods in UTC, personal stats in local time** — Accepted — 2026-10-19

**D-013 — iOS "ring until done" via nag chain** — Accepted — 2026-10-19
AlarmKit's alert always has a Stop button, so persistence is emulated with pre-scheduled follow-up alarms + dead-man's switch while the camera is active (doc 04 §5.2).

**D-014 — Leaderboard streak = pure streak (no freezes)** — Accepted — 2026-10-19
Prevents Pro/rewarded-ad freezes from becoming a paid competitive advantage.

**D-015 — Minimum age 16** — Accepted (revisit) — 2026-10-19
Simplest GDPR-safe option with chat, live video with strangers and ads.

**D-016 — Crash reporting Sentry, product analytics PostHog (EU)** — Accepted — 2026-10-19

**D-017 — Display font Barlow Condensed (SIL OFL)** — Accepted — 2026-10-19

**D-020 — iOS Xcode project generated by XcodeGen** — Accepted — 2026-10-19
`ios/project.yml` is the source of truth; `Pushly.xcodeproj` is generated and gitignored. Avoids merge conflicts in `project.pbxproj` and lets CI create the project. Tool: XcodeGen (MIT).

**D-021 — Feature modules are created when their phase starts** — Accepted — 2026-10-19
Phase 0 creates only `Core`, `DesignSystem`, `RepEngine` (iOS) and `:core:common`, `:core:designsystem`, `:engine:rep` (Android). Other modules from doc 03 §3 are added by the task that first needs them, with the same names.

**D-022 — DB tests also run on plain Postgres** — Accepted — 2026-10-19
`tools/db-sandbox` (Supabase stub + pgTAP-subset shim) runs migrations and tests without Docker. The real `supabase test db` remains the reference; tests may only use pgTAP functions present in the shim (`plan, ok, is, isnt, throws_ok, lives_ok, finish`) — extend the shim if more are needed.

**D-023 — `pg_cron` is enabled in the cron migration, not in 0001** — Accepted — 2026-10-19
Keeps early migrations runnable where pg_cron isn't installed.

**D-024 — Executable reference rules generate the shared test vectors** — Accepted — 2026-10-19
`tools/reference` (Python) is the executable spec for alarm occurrences, trophies, leagues, wake points and clan-war caps; vectors are generated, never hand-edited. SQL and both apps must match the vectors.

**D-025 — Android Phase 0 versions** — Accepted — 2026-10-19
AGP 8.13.0, Kotlin 2.2.20, Gradle 8.14.3, Compose BOM 2025.09.00, compileSdk/targetSdk 36, JVM target 17 (no toolchain download). Upgrade freely when Android Studio suggests; record here.

**D-026 — Light-mode lime changed to #679C00** — Accepted — 2026-10-19
`#6FA800` was 2.89:1 on white (needs 3:1 for graphics).

**D-027 — Android DI: manual composition for now, Hilt later** — Accepted — 2026-10-19
Phase 1 wires a handful of objects in `MainActivity`; Hilt (+ KSP version coupling to Kotlin) is added when the object graph grows (alarm/camera phases). CLAUDE.md §5 still targets Hilt.

**D-028 — Backend SDK versions** — Accepted — 2026-10-19
supabase-swift ≥ 2.52.0 (MIT); supabase-kt BOM 3.1.4 (MIT) with Ktor OkHttp engine 3.1.3 (Apache 2.0); kotlinx-serialization 1.8.1, coroutines 1.10.2, lifecycle 2.9.0 (Apache 2.0).

**D-029 — Sign-in methods in Phase 1: email 6-digit code (both), Sign in with Apple (iOS)** — Accepted — 2026-10-19
Google sign-in needs OAuth client IDs from the founder's Google Cloud account; added as soon as they exist. Apple requires Sign in with Apple only when other third-party logins are offered, so iOS stays compliant either way.

**D-030 — Offline / unconfigured builds run in guest mode** — Accepted — 2026-10-19
Without a configured backend (fresh checkout, CI) or when the profile fetch fails offline at launch, the app opens the tabs as guest instead of blocking. The alarm must work without an account (CLAUDE.md §4.4).
